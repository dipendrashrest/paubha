The Paubha CLI fetches source from the registry on
[paubha.tech](https://paubha.tech) and copies it into your codebase, with
no runtime package.

```bash
npx paubha@latest [command]
```

## init

Use the `init` command to set up configuration and shared dependencies for an
existing project.

`init` creates `components.json`, writes the design tokens and Tailwind v4
`@theme` mapping, adds the `cn()` helper, and installs `clsx`,
`tailwind-merge`, and `class-variance-authority`.

```bash
npx paubha@latest init
```

What it writes (defaults from `components.json`):

- `styles/tokens.css`: primitives + semantic tokens (light and dark)
- `styles/theme.css`: Tailwind v4 `@theme` mapping
- `lib/cn.ts`: `cn()` helper
- `components.json`: registry URL and path aliases

Existing files are skipped unless you pass `--force`. Safe to re-run.

Then import the generated CSS after Tailwind. See
[Installation](/docs/installation).

### Options

```
Usage: paubha init [options]

write tokens.css, theme.css, cn(), and install core dependencies

Options:
  --cwd <path>  the working directory. defaults to the current directory.
  --force       overwrite existing files. (default: false)
  -h, --help    display help for command
```

| Option | Description |
| --- | --- |
| `--cwd <path>` | Run against another project root |
| `--force` | Overwrite existing files |

## add

Use the `add` command to copy components (and their dependencies) into your
project.

Requires `components.json`; run `init` first.

```bash
npx paubha@latest add button
```

Add multiple components at once:

```bash
npx paubha@latest add button avatar tabs
```

`add` fetches `{registry}/{name}.json`, walks `registryDependencies`
recursively, dedupes shared files, and installs any npm packages listed on
those items. Example: `add field` also pulls in `input`.

Unknown names fail with the list of components the registry currently
publishes.

### Options

```
Usage: paubha add [options] <components...>

copy one or more components into your project

Arguments:
  components    component name(s), e.g. button avatar

Options:
  --cwd <path>  the working directory. defaults to the current directory.
  --force       overwrite existing files. (default: false)
  -h, --help    display help for command
```

| Option | Description |
| --- | --- |
| `--cwd <path>` | Run against another project root |
| `--force` | Overwrite existing files |

```bash
# Overwrite a component you already customized
npx paubha@latest add button --force

# Target another project root
npx paubha@latest add button --cwd ./apps/web
```

## components.json

`init` writes this at the project root. `add` reads it on every run.

```json
{
  "$schema": "https://paubha.tech/schema.json",
  "registry": "https://paubha.tech/r",
  "aliases": {
    "components": "components/ui",
    "lib": "lib"
  },
  "tailwind": {
    "tokens": "styles/tokens.css",
    "theme": "styles/theme.css"
  }
}
```

| Field | Description |
| --- | --- |
| `registry` | Base URL for registry JSON (`/r/{name}.json`) |
| `aliases.components` | Where UI files land |
| `aliases.lib` | Where helpers like `cn.ts` land |
| `tailwind.tokens` / `tailwind.theme` | Paths `init` uses for the CSS files |

Override the registry for a single command without editing the file:

```bash
PAUBHA_REGISTRY_URL=http://localhost:3000/r npx paubha@latest add button
```

`PAUBHA_REGISTRY_URL` wins over `components.json`.

## Registry

Components are served from `https://paubha.tech/r/{name}.json`, following
the [shadcn registry schema](https://ui.shadcn.com/schema/registry.json). You
can also install with the shadcn CLI:

```bash
npx shadcn@latest add https://paubha.tech/r/button.json
```

### Building the registry (contributors)

The monorepo source of truth is `packages/registry`. After changing a
component:

```bash
pnpm build:registry
```

That emits `apps/www/public/r/*.json` for the docs site to serve.
