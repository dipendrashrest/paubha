## Usage

```tsx
import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuItem,
  DropdownMenuTrigger,
} from "@/components/ui/dropdown-menu";

<DropdownMenu>
  <DropdownMenuTrigger asChild>
    <Button variant="secondary">Open menu</Button>
  </DropdownMenuTrigger>
  <DropdownMenuContent>
    <DropdownMenuItem>Edit</DropdownMenuItem>
    <DropdownMenuItem destructive>Delete</DropdownMenuItem>
  </DropdownMenuContent>
</DropdownMenu>
```

Items have five states: default, hover (`bg-secondary-hover`), keyboard focus
(`bg-secondary` plus the `glow-focus` ring, via `focus-visible` so it only shows
for keyboard-driven focus), pressed (`bg-brand-subtle` with `fg-brand` text) and
disabled (`fg-disabled`). `destructive` swaps every fill and the label to the
error tint.

The panel is portalled to `<body>` on the `--z-popover` layer, so a menu opened
from inside a Dialog or Modal renders above it.

## Accessibility

<A11yCallout>
  <ul>
    <li>
      <strong>Roles.</strong> <code>role=&quot;menu&quot;</code>, items{" "}
      <code>role=&quot;menuitem&quot;</code>.
    </li>
    <li>
      <strong>Keyboard.</strong> Arrow keys navigate (disabled items are
      skipped), Home/End jump, typing a letter jumps to a matching item,
      Enter/Space selects, Escape closes and returns focus to the trigger.
    </li>
    <li>
      <strong>Focus.</strong> Trapped within the open menu; a visible{" "}
      <code>glow-focus</code> ring shows for keyboard-driven focus specifically.
    </li>
  </ul>
</A11yCallout>
