## Usage

```tsx
import { Avatar, AvatarAddButton, AvatarGroup, AvatarProfilePhoto } from "@/components/ui/avatar";

<Avatar src="/maya.jpg" alt="Maya Chen" />
<Avatar initials="MC" alt="Maya Chen" indicator="online" />
<AvatarProfilePhoto src="/maya.jpg" alt="Maya Chen" verified />

<AvatarGroup max={3}>
  <Avatar src="/maya.jpg" alt="Maya Chen" />
  <Avatar src="/rio.jpg" alt="Rio Patel" />
  <Avatar initials="KO" alt="Ken Okada" />
  <Avatar initials="AS" alt="Ana Silva" />
</AvatarGroup>
```

## Examples

### Sizes

xs 24px · sm 32px · md 40px · lg 48px · xl 64px · 2xl 80px.

<AvatarSizes />

### Type

`type` picks `image`, `initials` (`bg-brand-subtle` / `fg-brand`), or `icon` (Lucide `User`). When omitted it's inferred from what you pass.

<AvatarTypes />

### Image and fallback

A missing or failing `src` falls back to initials; if neither `initials` nor `alt` can produce letters, the avatar shows the user icon.

<AvatarImageFallback />

### Indicator

`online` (`bg-success-solid`) and `offline` (`fg-disabled`) render a presence dot with a `bg-primary` cutout; `company` and `verified` render a `Building2` / `BadgeCheck` badge in `fg-brand`. The indicator is also written into the accessible name — keep a visible text label too when presence or verification affects a decision.

<AvatarIndicators />

### Profile photo

`AvatarProfilePhoto` is the large profile identity: sm 72px · md 96px · lg 160px, with a 4px `bg-primary` ring, `shadow-md`, and an optional `verified` badge.

<AvatarProfilePhotoExample />

### Avatar group

Stacked, overlapping avatars with a `+N` overflow chip (`bg-secondary` / `fg-secondary`). Each face gets a `border-default` ring and a `bg-primary` stack cutout.

<AvatarGroupExample />

### Label group

Pairs an avatar with a name and optional secondary text (email, role). `size` sm/md/lg/xl sets the avatar (32–64px) and the label type scale together.

<AvatarLabelGroupExample />

### Add-member button

A dashed-border circular button for adding another person to a group. Sizes match Avatar's own `md`/`lg`/`xl`. The hover state (`border-brand` + the signature glow-focus shadow) is also applied on `focus-visible`, since Figma's mockup only shows hover but every interactive component needs a visible keyboard focus indicator.

## Accessibility

<A11yCallout>
  <ul>
    <li>
      <strong>Role.</strong> Each avatar is <code>role=&quot;img&quot;</code> with an{" "}
      <code>aria-label</code> from <code>alt</code> (or <code>initials</code>). The indicator is
      appended to that name, e.g. <code>Maya Chen, online</code> or{" "}
      <code>Maya Chen, verified</code>, not a nested labelled node. Indicator glyphs are{" "}
      <code>aria-hidden</code>. The inner <code>&lt;img&gt;</code> uses <code>alt=&quot;&quot;</code> so it
      isn't announced twice.
    </li>
    <li>
      <strong>Keyboard.</strong> Avatar is presentational. It is not focusable and has no
      activation keys. Wrap it in a link or button if it should be interactive.
    </li>
    <li>
      <strong>ARIA.</strong> <code>AvatarGroup</code> uses <code>role=&quot;group&quot;</code>.
      Overflow is its own <code>role=&quot;img&quot;</code> labelled{" "}
      <code>N more</code>.
    </li>
    <li>
      <strong>AvatarAddButton</strong> is a native <code>&lt;button&gt;</code>:
      Enter/Space activates, and it accepts an accessible name via{" "}
      <code>aria-label</code> (defaults to <code>&quot;Add&quot;</code>). Its
      focus ring uses the same <code>shadow-glow-focus</code> treatment as its
      hover state.
    </li>
  </ul>
</A11yCallout>
