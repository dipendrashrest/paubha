## Usage

```tsx
import { Input } from "@/components/ui/input";

<Input placeholder="you@example.com" />
```

Input renders as a bordered wrapper around a plain `<input>` (so icon slots
can sit inside the same border). Pair it with [Field](/docs/components/field)
for a label, helper text, and error message wired up with the right ARIA
attributes. Input itself is deliberately just the control.

### Add-ons

`leadingText` shows a fixed prefix such as a URL scheme. `leadingAddon` and
`trailingAddon` hold a separate control, such as a currency selector — give
it its own accessible label. Composed types are designed for `sm` and `md`;
`2xl` is for the plain input only. For multiple values as tags, use
[Tag Input](/docs/components/tag-input).

## Accessibility

<A11yCallout>
  <ul>
    <li>
      <strong>Role.</strong> Native <code>&lt;input&gt;</code>, so{" "}
      <code>role=&quot;textbox&quot;</code> is implicit.
    </li>
    <li>
      <strong>Label.</strong> Input has no label of its own: it requires an
      associated label via <a href="/docs/components/field">Field</a>.
    </li>
    <li>
      <strong>Error.</strong> The <code>error</code> prop sets{" "}
      <code>aria-invalid=&quot;true&quot;</code> on the real input, which drives the
      error border via CSS <code>:has()</code> on the wrapper.
    </li>
    <li>
      <strong>Focus.</strong> The wrapper shows the <code>glow-focus</code> ring on{" "}
      <code>focus-within</code>, so focusing the inner input rings the whole
      bordered box, not just the text.
    </li>
    <li>
      <strong>Add-ons.</strong> Leading text is presentational and not part of
      the value. Add-on controls are separate tab stops with their own labels.
    </li>
  </ul>
</A11yCallout>
