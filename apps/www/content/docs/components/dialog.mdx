## Usage

```tsx
import {
  Dialog,
  DialogAction,
  DialogActions,
  DialogBody,
  DialogCancel,
  DialogContent,
  DialogDescription,
  DialogTitle,
  DialogTrigger,
} from "@/components/ui/dialog";
import { Button } from "@/components/ui/button";

<Dialog>
  <DialogTrigger asChild>
    <Button variant="secondary">Discard changes</Button>
  </DialogTrigger>
  <DialogContent>
    <DialogBody>
      <DialogTitle>Discard changes?</DialogTitle>
      <DialogDescription>
        Unsaved changes to Website redesign will be lost.
      </DialogDescription>
    </DialogBody>
    <DialogActions>
      <DialogCancel>Keep editing</DialogCancel>
      <DialogAction>Discard changes</DialogAction>
    </DialogActions>
  </DialogContent>
</Dialog>
```

## Accessibility

<A11yCallout>
  <ul>
    <li>
      <strong>Role.</strong> Built on Radix <strong>AlertDialog</strong> (not plain
      Dialog): <code>role=&quot;alertdialog&quot;</code> with{" "}
      <code>aria-modal=&quot;true&quot;</code>, <code>aria-labelledby</code> pointing
      at <code>DialogTitle</code> (the decision) and <code>aria-describedby</code> at{" "}
      <code>DialogDescription</code> (its consequence).
    </li>
    <li>
      <strong>Focus.</strong> On open, focus lands on <code>DialogCancel</code>, the
      safe action. Tab and Shift+Tab stay inside; background content is inert.
    </li>
    <li>
      <strong>Escape</strong> takes the cancel path and restores focus to the trigger.
      Unlike <a href="/docs/components/modal">Modal</a>, clicking outside does{" "}
      <strong>not</strong> close it. The user must make an explicit choice.
    </li>
    <li>
      <strong>Focus ring.</strong> Visible on Tab via <code>shadow-glow-focus</code> on
      both actions.
    </li>
    <li>
      <strong>Motion.</strong> Opens with a <code>duration-fast</code> (100ms) ease-out
      fade; instant under <code>prefers-reduced-motion</code>.
    </li>
  </ul>
</A11yCallout>

## When to use

Use for confirmations before destructive or irreversible actions: deleting items,
discarding changes, revoking access. Requires an explicit user decision.

**Do:**
- Name the decision in the title ("Discard changes?"), not a generic "Are you sure?"
- Explain the actual consequence, naming the affected item
- Keep the safe action (Cancel, Keep editing) alongside the decision action
- Use the error variant for destructive actions

**Don't:**
- Use for informational updates, use [Alert](/docs/components/alert) or [Toast](/docs/components/toast) instead
- Chain multiple dialogs
- Default-focus the destructive action
